## 2026-10-08 本地双线队列

## 2026-09-18 内存安全人工暂停

- 进程内存上限、系统空闲内存预留或阶段预分配触发预算时，当前 worker 停在 `paused`，保留队列位置，后续任务不启动；进度小窗显示具体原因和“继续任务”，后台小窗在 Windows 任务栏闪烁而不抢焦点。工坊任务列表也可手动继续。
- 每次点击继续均重新采样进程树和系统可用内存，并重新检查该阶段的分配需求；不足则维持暂停，不自动放宽预算。调整本批内存设置后仍需手动点击继续。FFmpeg 阶段先停止可重试命令，安全通过后从原输入重做该命令。取消可以唤醒暂停。磁盘、资源等非内存故障照常失败。
- 仅在本机服务与 worker 持续存活时保留暂停现场；服务重启后将旧 `paused` 记录标为 `interrupted`，不擅自重新运行，旧 queued 仍退回 pending。进度页或浏览器关闭不会使后台任务自动恢复。

## 运行

```powershell
node experiments/offline-export/run.cjs 4902005026 all
node experiments/offline-export/run.cjs "C:\path\to\202701011.json" all
node experiments/offline-export/audit.cjs 202701011
node experiments/offline-export/run.cjs "C:\path\to\202701002.json" offline

node experiments/offline-export/audit-media.cjs 201002001
node experiments/offline-export/audit-media.cjs 201002001 spine-fixed-20260917
```

需要本机 Edge 或 Chrome、Playwright、可用的 WebCodecs H.264 编码器及 FFmpeg。可通过 `SSV_CHROMIUM`、`SSV_PLAYWRIGHT`、`SSV_FFMPEG`、`SSV_FFPROBE` 指定路径。默认值仅用于当前开发电脑，不能直接作为便携包配置发布。

第三个参数可为 `preflight` / `prepare`（只检查、准备资源，不生成影片）、`offline`（默认）、`branch-preview`、`verify-branches`（只跑完整三分支时间线，不生成视频）、`reference`、`determinism`、`all`，或仅重做音频最终处理的 `mix`。生成物位于 `exports/offline-proof/<剧情ID>/`。同一 ID 的再次验证会覆盖该验证目录内的同名结果，不触碰源资源目录。分支短片的 `determinism` 复验需设置 `SSV_BRANCH_PREVIEW=1`。

设置 `SSV_PROOF_RUN_TAG`（仅英文字母、数字、连字符、下划线）可将本次结果另存到 `exports/offline-proof/<剧情ID>/<标签>/`，复用原验证目录的源 JSON 和缓存，不覆盖之前的样片。例如 `$env:SSV_PROOF_RUN_TAG='live-ending-20260917'`。

当前通道：无窗口 Chromium → 同款渲染器 → WebCodecs H.264 逐帧编码 → 小体积编码包写盘 → FFmpeg 封装及离线音频混音 → MP4。不是录制桌面或系统外放声音。
维持 balanced 渲染规格 1704×960，由编码器缩放到 1920×1080 / 60fps；不是提升原始素材分辨率。H.264 为有损编码，当前目标码率 30Mbps。
每帧使用显式的 60fps 时间戳；只允许一个未确认帧，返回时间戳不符、编码器无响应或最终帧数不符均中止。编码器的低延迟设置仅用于避免等待后续输入帧，不驱动剧情时间。
默认每秒实际生成最多 18 帧，可用 `SSV_PROOF_WALL_FPS=1..30` 设定上限；电脑忙时自动降到 12 或 6 帧，并按每帧实际工作时间主动让出计算时间。输出仍是 60fps，画质、时间戳、动作速度不变；代价是生成慢于影片实际时长。
编码配置请求 `prefer-hardware`，但最终设备由浏览器选择，不能据此宣称一定使用 NVIDIA NVENC。

## 2026-09-17 后台负载保护与资源预检

- 同一工程只允许一个导出任务，独占锁不会覆盖在运行的任务。已退出进程留下的锁可恢复；无法确认归属的锁拒绝自动清除。
- Node、此任务的 Chromium 子进程和 FFmpeg 使用低优先级；FFmpeg 视频解码、PNG 编码限制单线程。每约 3 秒采样系统 CPU、可用内存、导出进程私有内存及输出磁盘空间。该实现目前要求 Windows；不会将只统计 Node 的内存冒充整棵进程树占用。
- 默认导出预算为物理内存的四分之一、最多 3072 MiB；系统保留内存为物理内存的 10%、至少 1536 MiB。可通过 `SSV_PROOF_MEMORY_MIB`、`SSV_PROOF_RESERVE_MIB` 配置。压力较高时降速，系统余量不足时暂停逐帧生成，最多等待 60 秒；超出自身预算、持续缺内存或磁盘不足则明确中止。外部 FFmpeg 阶段无法安全冻结虚拟时钟，压力过高时直接终止该阶段。
- 暂停只发生在生成进度上，不在影片中留下停顿。不是降低分辨率、跳帧或调整剧情的 `wait`；原来的单帧确认队列保留。预检后回收已释放的解码对象，大块音频后处理与纹理准备先估算新增占用，不足时不开始分配。
- 这是协作式预算保护，不是操作系统硬内存配额。采样存在间隔，也不等于测量/限制独立显存；不能据此保证所有电脑零卡顿。整段音频压缩器仍需连续缓冲，长剧情若超预算会拒绝，尚未通过分块处理改变原音效。
- 预检覆盖启动脚本、双语字体实际加载、UI 图集依赖、Spine JSON/atlas/全部纹理页、图片解码、语音解码、动态卡图及分支转场视频的逐帧解码、H.264 配置支持。资源和启动文件缺项汇总到 `preflight-report.json`；报告明确区分 `incomplete` / `failed` / `passed`，不能把未完成检查误称为通过。
- 缺失资源按既有、已验证的下载地址逐项获取；单文件下载上限 128 MiB，有超时、有限重试，404 等确定缺失不重复请求。已经存在但损坏的缓存会报出具体路径，不静默覆盖。`SSV_PROOF_OFFLINE=1` 可关闭资源下载。
- 预检通过后的浏览器仅允许本机资源访问；不会在演出途中临时访问资料站补图。PCM 缓存关联源 SHA-256 和完整样本数，失败的 `.partial` 不当成成功缓存。完整封装成功后才将 `.offline.partial.mp4` 改成最终文件名。
